# 柏宝书 ⇄ 月夜来信小手机（1.3.4 / 1.6.3）

联动在同一酒馆页面通过 `window.STBaiBaiBook.phone` 完成，不增加服务端插件。

## 读取接口和权限

- `isEnabled()`：手机联动总开关。
- `canReadMemory()`：总开关开启且`phoneBridge.shareMemory`允许读取。
- `getBrief({ historyChars?, anchorChars? })`：当前聊天的摘要、锚点、时间地点、人物、未完计划、物品、生活细节。读取关闭时抛出可读错误。
- `getNpcProfile(name)`：读取关闭时返回空字符串。
- `getAnchor()`：读取关闭时返回null。

`apiVersion`仍为1，添加的是`canReadMemory`与简报的`items`字段。手机兼容没有`canReadMemory`的旧版提供者，按`isEnabled`退化；要使用书侧独立读取开关，请同时升级两端。

## 手机生成链路

`PhoneActions.perform → baibaiFilterInput → prepare → baibaiEnrichRequest → router.call`。

- 每次生成清空短期简报缓存，读当前记忆，不复制整库。
- 读取关闭时从请求副本中过滤`bb`导入记忆，保留存档；旧消息和普通衍生摘要不自动撤回。
- 人物生成通过`actorContext`按人物读取。群聊和公开动态不带全局私密摘要/锚点。
- 玩家日记、备忘、清单、日历、规划、记忆整理通过公共请求入口补充参考；角色日记透传本人上下文。
- 生成期间更改读取策略会拒绝该次旧结果提交。
- 逐字原文、消息ID、正文楼层等记忆/进度校验仍然保留，不能用简报伪造证据。

手机记忆页可切换读取或预览参考。设置键仍为`ui.baibai.brief`，保留旧开关选择。

## 回写与导入

`pushNotes`仍只写柏宝书的external记录，不修改原摘要森林。手机回写由独立`ui.baibai.push`控制；手动立即回写也不绕过关闭的开关。更新去重签名在写入成功后才提交，失败可以重试。

静态「导入柏宝书记忆」保留，但新副本默认`audience: ['user']`，不再用姓名出现推断知情权限。导入不会持续同步源变化。带`bb`标记的记录不再次进入主模型的手机注入或手机记忆世界书，避免重复回灌。

原有数据存储键、消息归属和手机脚本ID保持不变。没有做全部旧同步问题重构，尤其日程结束状态/历史权限仍应参考已知限制。

完整用户操作与边界见 [LOCAL_EDITION_1.3.3.md](LOCAL_EDITION_1.3.3.md)。

## 1.6.3 事项生命周期
手机会用稳定 ID 更新取消/完成/停用的日程和约定，并取消旧置顶；从手机完整事项集合删除的旧有效事项写入结束标记。消息和朋友圈仍按窗口追加，不作整来源 replace，不删除窗口外历史。
