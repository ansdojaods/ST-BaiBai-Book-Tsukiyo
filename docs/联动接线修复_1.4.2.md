# 百宝月夜书 1.4.2：联动接线修复（与小手机 2.9.5 配套）

> 这份文档解释 **v1.4.2 改的 8 处接线/去重**、每处的证据、验证方式与已知边界。
> 起因是一次「三者联动」复查：能力都做出来了，但有几根线没插上。

## 1. 剪辑台的召回从未自动生效（P0）

**证据（修改前）**：面板自己写着契约「生成前由宿主调用一次召回、生成结束后由宿主清空——剪辑台不会自己塞第二次」（`ui/panel.ts`），
而 `recall()` 的调用点只有面板按钮、`clearInject()` 只有面板按钮与「召回被关」分支；宿主 `src/index.ts` 的 `bbs_generateInterceptor` 只跑
柏宝书自己的 `handleAnchorIntercept / handleGenerationIntercept / runVectorRecall`。此外 `setExtensionPrompt` 是**持久化**的
（`memory/inject.ts` 注释原文），手动点一次「现在召回并注入」后，这个块会跟着之后每一次生成。

**现在**：
- `src/index.ts`：放行路径上、`runVectorRecall()` 之后调 `runEditorRecall()`（`host.ts` 暴露，内部 `service.recall({})`，异常吞掉不影响生成）；
- `service.onGenerationEnded()`：把「上次召回」记进 `state.inject.last` 后 **清空注入槽**（新增 `pendingInject` 标记承担「一次性」语义，`lastInjection` 仍保留给面板显示）；
- 结果：一次生成恰好注入一次；剪辑台关了/召回关了时 `recall()` 内部会清槽。

## 2. 「汇入小手机记录」按钮是死的（P0）

`options.notesProvider` 只有定义（`ui/panel.ts`）没人传（`host.ts` 创建实例时只传了 `autoInit/title`），点下去永远提示
「没有可汇入的手机记录」；`mergePhoneNotes()` / `mergeExternal()` 全仓库无人调用。
**现在**：`host.ts` 传入 `notesProvider` —— 取 `externalState.notes` 里 `source === 'tsukiyo-phone'` 的记录，映射成 `{id,kind,title,text,floor,pinned}`。
手机推来的消息/约定/动态/心迹可以直接一键汇进剧情状态账本（标注 `source: "phone"`，与正文摘要分开）。

## 3. 自动摘要归属二选一（P0，最影响 token）

**修改前**：柏宝书摘要森林 `autoSummaryEnabled` 默认 true、剪辑台 `cfg.auto.enabled` 默认 true —— 同一段剧情可能被摘两次，
「摘要」页与剪辑台还会显示两个互相矛盾的缺口数字。迁移方案里写过「并存期间只准一边开自动摘要」，但代码/UI 都没有强制。

**现在**：
- 新设置 `editorOwnsAutoSummary`（默认 false = 柏宝书），位置：**设置 → 摘要设置 →「自动摘要归属」**（下拉：柏宝书 / 剧情剪辑台）；
- `engine.ts → maybeSummarizePrevAi()`：归属在剪辑台时直接早退（时间标签、旧楼隐藏、积压拦截仍跟随 `autoSummaryEnabled`，不受归属影响）；
- `HostPort.autoSummaryAllowed()`：宿主回答「自动摘要是否归剪辑台」，剪辑台在 `onGenerationEnded()` 里据此让位；`info().autoAllowed` 与面板设置页会显示当前归属；
- 旧宿主没实现该方法时按「允许」处理，行为与本轮之前一致。

> 后续可选（未做）：按迁移方案把剪辑台 `tree` 与摘要森林 `childIds/covers` 做适配层，全仓库只留一份摘要数据。

## 4. 小手机不再「两头不管」（P0，手机侧配套）

`capability()` 现在返回 `{ available, apiVersion, pluginVersion, enabled, mode }`。小手机 v2.9.5 会在
`enabled === false`（剪辑台总开关关着）时**继续自己管**楼层记忆，并在工作台顶部写明状态；
总开关打开后下一次探测/事件会自动恢复让位。

## 5. 面板不再空转（P1）

`st-baibai-book:changed` 挂在 ST 的逐条消息事件上（`public/register.ts`），而面板默认是收起的、`render()` 又是全量重建 DOM（每次还伴随
`port.listFloors()` 全聊天扫描）。现在：**面板收起时只更新镜像与角标，不重建 DOM**；同一轮多次事件合并成一次（120ms）。

## 6. 草稿不再「悄悄躺在收起的面板里」（P1）

- 自动生成草稿后 `toast` 提示一次（「第 X–Y 楼摘要草稿已生成，待确认」）；
- 魔杖菜单「剧情剪辑台」显示角标：`剧情剪辑台 · N`（`features/memory-editor/badge.ts`，菜单注入时读一次、状态变化时更新）。

## 7. 双向打开入口（P1）

`memoryEditor` 增加 `open() / close() / toggle()`（宿主通过 `CreateOptions.panelControls` 注入，指向 `toggleMemoryEditorPanel`）。
小手机工作台「楼层记忆归属」卡片新增「打开剪辑台」按钮；老版本没有该方法时给指引而不是报错。

## 8. 清理与去重（P2）

- 删除无人引用的 `describeEditor()`；
- `mountMemoryEditorPanel()` 里 `!panelBody.contains(panelBody.lastElementChild ?? panelBody)` **恒为假**（自身总被包含）→ 改为查 `:scope > .bme-root`；
- `host.ts` 里挂在 `floorRole()` 头上的「兼容旧调用点」注释是错的，已更正；
- 「恋爱心迹」注入可关：`phoneBridge.injectHeart`（默认开）。关闭后 `phone_heart` 记录仍在「联动」页与摘要材料里，只是不塞进主模型
  —— 它与柏宝书自己的「锚点日记」内容相近，两个都注入容易重复占上下文。

## 9.5 跨仓库契约测试（P2-11）

手机 v2.9 的记忆工作台与剪辑台 `core/*` 是同一套算法（覆盖块切分、账本键归一）的两份实现——引擎没装时手机自管，是有意设计。为避免两份实现走岔：

- 两侧各放一份**同一份夹具**的契约测试：柏宝书 `tests/memory-editor/contract.test.cjs`（并入 `npm run test:editor`，60 → 65 项）、手机 `tools/test_contract.cjs`（并入手机 `npm test`）。
- 夹具块用 `// @contract-fixture:begin/end` 标出；两个仓库的检查目录同时存在时，两侧测试会互相比对夹具，漂移即红（只在一个仓库里跑则跳过，不误报）。
- 手机源码 `src/services/memory-studio.js` 顶部已标注【待命实现】：这条线只修安全与兼容、不再新增能力，新能力一律加到剪辑台。

## 10. 已知边界

- 仍未做真实酒馆 / 真实 API 的端到端验证；剪辑台模块测试用假宿主（`tests/memory-editor/fake-host.cjs`）。
- 摘要森林与剪辑台摘要树仍是**两棵树**：本轮只保证「同一时间只有一边自动摘」，没有合并数据。
- `listFloors()` 仍是每次现扫（本轮把「面板收起时的高频重绘」去掉后，调用频率已降到每次生成 2–3 次，
  长聊天若仍觉卡顿，可再加 `(chatId, chat.length, rev)` 记忆化）。

联动协议（`capability()` 新字段、事件 detail 形状、`open/close/toggle`、`mergePhoneNotes`、归属闸门与手机 2.9.5 侧对应字段）已整理进 [PHONE_BRIDGE.md](PHONE_BRIDGE.md)（协议 v2）。
