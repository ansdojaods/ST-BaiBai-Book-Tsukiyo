本次继续处理第二轮源码审查（上游 `9e42ccd68c0cc0ea7166d5b2f31553005ab61fe6`）未完成的问题，以此前已交付的主扩展 1.3.3 / 手机 1.6.2 为功能基线。没有推送 GitHub，也没有修改或部署到用户服务器。

## 一、升级前必读

1. **先用 SillyTavern 导出完整聊天备份，并保留旧扩展/手机脚本。** 记忆快照不包含聊天正文、全部 swipe 或手机自身全部存档，不能替代完整聊天备份。
2. 主扩展通过更新前端扩展文件/仓库安装：保留源码包中的 `manifest.json` 与 `dist/`，刷新酒馆。不要把源码 ZIP 当成角色卡或酒馆助手脚本导入。若托管平台不允许更新前端扩展，请交给有权限的管理者；不需要安装白鸟服务器插件。
3. 手机通过酒馆助手脚本库导入 `phone/dist/月夜来信小手机_酒馆助手导入版_v1.6.3_柏宝书联动.json`。稳定脚本 ID 不变；避免旧独立版与卡内手机同时运行。
4. 升级不会主动清空现有聊天中的叶子摘要、锚点、外部记录或手机导入记忆。打开重要聊天后，建议重新导出本版 **v2 快照**，等待聊天保存完成。
5. **旧 v1 快照/旧恢复点没有足够的消息身份信息，新版拒绝直接整份恢复。** 不会按下标猜测，也不会悄悄丢掉叶子再报告成功。旧恢复点可在融合页单独导出；先保留旧文件和完整聊天备份，如确需使用旧快照，应在旧版与对应聊天的隔离副本中核对、恢复，再升级并生成 v2。不要在唯一的当前聊天上试错。

## 二、保留用户已要求的功能

- **现有楼层手写补摘**：摘要页 → 未摘要 AI 楼层 → 手写。无需 AI，不造虚拟楼，不覆盖已有有效摘要；只记录摘要及时间范围，不猜测物品/角色等 delta。
- **手机可选实时读取**：主扩展的读取许可与手机“使用柏宝书记忆生成”均可关闭。消息、朋友圈、日记、规划等入口沿用已完成的读取接入。读取和回写开关独立，关闭读取不删除手机存档里的导入副本。
- **无白鸟额外后端**：没有白鸟探测、上传、自动远程备份、冲突重试或相关 404 提示。保留聊天 metadata 恢复点、回收站和 JSON 导出导入。这里的“本地”指依附现有 ST 聊天存档，并非只存在浏览器 localStorage。

## 四、具体行为与兼容边界

### 会话和异步任务

- 票据包含聊天数组引用、聊天/角色或群组身份和 CHAT_CHANGED 代次，防止 A→B→A 旧请求回流。
- 摘要读取的消息前缀、正文/swipe/叶子以及相关记忆输入变化后，旧结果被丢弃。不会把过时批量响应转为逐楼回退继续发请求。
- 这不是底层网络取消机制。已经发出的 LLM 请求可能仍计费；普通摘要忙碌锁可能等待旧请求返回/超时后才释放。已交给宿主执行的单条命令不能被本扩展撤回；护栏阻止后续陈旧提交/命令。
- 移除了摘要引擎输出原始 LLM 返回正文的调试日志；没有完成所有依赖/宿主日志的隐私审计。

### v2 快照和恢复

- 新快照含消息稳定 ID、正文指纹与 swipe、聊天归属、森林、叶子、聊天模板、锚点、外部记录和继承的向量 bundle 引用。
- 恢复不会重建已删除的聊天正文。若快照后只追加新消息、原前缀不变，可回滚记忆；回滚是**整份替换**，快照之后新形成的记忆会被撤销，新的正文不会被删除。
- 删除/重排/更改原消息、改变 swipe 或换聊天时，完整快照整份拒绝。它不是跨聊天记忆迁移工具；跨聊天使用“带数据创建新对话”。
- 消息 ID 写入 `extra.bbs_message_id`，随现有 ST 聊天保存。正文指纹用于错配检测，不是加密签名；不把未经信任的文件当作可信剧情来源。
- 新 schema 不自动猜测旧/未来版本的结构。旧点可导出保留；历史回收条目缺少身份/父边信息时，也不能凭空补出这些信息。
- 恢复前副本预检防止已知坏输入造成半覆盖；**不承诺服务器磁盘事务或保存失败后的分布式原子回滚**。实际持久化仍由 ST 的 saveChat/saveMetadata 负责。
- 恢复点仍按设置限制数量，并增加总序列化体积约 8 MiB 的软预算：优先删最旧点，至少保留最新一份，即单份超限时不悄悄丢掉唯一恢复副本。导入快照还有约 20 Mi 字符的体积检查。

### 回收站

- 单条总结恢复原父边顺序；父节点/边已经改动时拒绝覆盖用户新编辑。
- 单叶/子树先检查所有身份和依赖，再提交。原消息不在、正文/swipe 改动、已经有新摘要、ID/父子关系冲突时，不部分成功后清空回收条目。
- 删除叶子/子树所剪掉的祖先也一起保存与恢复。旧版本已丢失的祖先/父边信息无法追溯重建；请用完整恢复点或人工处理。

### 带数据新聊天

- 携带最近窗口、历史摘要/派生状态、独立锚点、手机外部记录、聊天变量模板；向量 bundle 仍仅在原有向量功能启用且接口可用时沿用。未引入新的必装服务。
- 窗口内来源楼层精确重映射；窗口外来源归到种子楼 0。窗口外有效正文锚点成为注明旧来源的手工继承锚点；已失效/排除的版本不会自动重新启用。
- 回收站和恢复点留在旧聊天，不搬进新聊天；手机自身完整聊天/应用存档不属于书侧 carryover 数据。
- 群聊仍不支持此创建操作。创建期间切换聊天或目标非空/身份不明确时停止写入；若宿主已创建空聊天，可能留下一个未填充的新聊天，不会自动删除它。

### 手机记录和权限

- 所有手机日程/本地约定状态参与生命周期同步，不再只挑未结束的小窗口；已结束记录取消置顶。
- 每来源超出 200 条时优先淘汰最旧非置顶，仍超出才淘汰最旧置顶。这是有损上限，不是无限历史归档。
- 超预算的大条目会跳过，可能导致预算很小时没有外部记录注入；不会把“第一条”无限塞入。
- 既往导入副本的 audience 不自动批量改写，因为无法区分旧自动猜测和用户手动授权。请检查旧手机存档里的知情范围。关闭读取不撤销已经写入历史生成消息或普通衍生摘要的旧信息。

## 五、验证与交付

本包 `verification/` 保存本轮最终运行日志、文件哈希和变更清单。测试均在本地/模拟宿主环境运行：真实导入源码/实际手机 bundle，模型响应和 ST 宿主接口用 mock；没有访问用户酒馆、真实 LLM 或真实备份服务。

本包最终结果：**12 个 Vitest 文件 / 298 项测试通过**（含 47 项新增安全回归），另有时间关系 810、向量深度 12、记忆回归 53 项脚本断言；**32 项手机实际 bundle 用例**及手机/Vue 模拟 UI 验证通过。类型检查、主扩展/手机重建和无白鸟产物检查均通过。

验证命令：

```bash
npm ci
npm run verify
```

包含：类型检查；完整 Vitest（含新安全行为回归和 Vue 交互）；时间/向量深度/记忆脚本断言；主扩展生产构建；无白鸟 endpoint/入口及保留功能检查；从原始手机基线应用补丁重建；手机实际 bundle 生成/同步回归；jsdom 模拟手机 UI。

测试通过不是在用户的托管 ST 上已经验证。上线后建议在**复制的测试聊天**手动检查：无 AI 手写补摘、手机读取开/关、锚点 swipe 切回、请求中切聊天、导出/恢复 v2、取消手机约定、带数据新建聊天。
